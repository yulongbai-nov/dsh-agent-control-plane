# Synthetic utility research — non-installable WIP

This is a fixture-only experiment against public upstream commit `b830ec950faba0a46dda564be3e2d854afed94f1`, lockfile SHA-256 `911b049924e8256d8d6e684235cf935ca75b28fd0dd46f0c3b316a51c2cf5dc1`. It registers the stable `run_utility` name in the genuine ToolRuntime but executes only injected inert synthetic functions. It does **not** run the real workflow engine, call a model, or establish E2E coverage.

Manual confirmation is a trusted test callback, not an authenticated human approval. State and deduplication are process-local; there is no durable registry, source authenticity, principal/workspace authorization, input schema registry, isolation, resource limits, durable idempotency, cross-process concurrency control, or revocation of running work. Do not use this with personal data, real credentials, untrusted code, or the installed app. Safe production integration is blocked on these requirements, including approved immutable source and a Host-owned approval bound to the intended action. A denial or crash during real execution can have an unknown outcome; no automatic retry guarantee is made here.

## Reproduction

In an isolated checkout of the exact upstream commit, prepare dependencies from the frozen lockfile with pnpm 11.28.5 and scripts and pnpmfile hooks disabled; do not use a real DSH installation. Copy `registry.mjs`, `registry.test.mjs`, and `host-tool.ts` to `synthetic-utility-wip/` at the checkout root, and copy `host-tool.spec.ts` to `packages/core/tools/tests/synthetic-utility-wip.host.spec.ts`. The test import expects exactly these paths.

Run `node --test synthetic-utility-wip/registry.test.mjs`. For the Host test use `node node_modules/vitest/vitest.mjs run packages/core/tools/tests/synthetic-utility-wip.host.spec.ts --no-file-parallelism --reporter=verbose` in an appropriate network-denying sandbox with profile and installed-app access excluded. `observed-sandbox-command.sh` preserves the exact command used on this machine, including absolute paths; inspect and adjust paths for a different environment. It is an evidence record, not an install script. Pin and review the toolchain and transitive dependencies independently before relying on another run.

## Synthetic Workflow Host characterization

The separate `workflow-host.spec.ts` passes 1/1 using the pinned real PTC Workflow Host and ToolRuntime, with an inert `return null` source, a fake PTC executor that returns a predetermined completed result without running source, a synthetic parent, a stub provider that fails if called, and a synthetic confirmation callback. It checks concurrent duplicate requests cause one Host start, promotion/rollback/disable, three completed run handles with awaited `dispose`, and zero child starts. It does not exercise a real PTC runtime or process, script execution, actual model or authenticated approval; counting awaited cleanup calls is not a proof of all runtime cleanup paths. The fixture uses process-local state and does not test revocation of already-started work. Test SHA-256 before and after the run: `c82cdd481400c3ba2220f75d1713d57d3a20217624d34f77eed43290b60e336c`; retained `workflow-host-test.log` SHA-256 `a3bd64bf5ade0375962a704717d749d7b58f0600132fa9a0f3c34ae9d863b4ea`. The existing Host adapter and registry had the hashes listed above before the run. `observed-workflow-sandbox-command.sh` records the reviewed no-network/profile-denying command; for reproduction, place the test at `packages/workflow/workflow-ptc/tests/synthetic-utility-host.spec.ts` after copying the adapter and registry to `synthetic-utility-wip/` as described above. The first run imported an unnecessary helper with an unavailable transitive `yaml` package and executed no tests; the retained successful run uses the narrower synthetic parent helper.

## Real PTC worker attempt: blocked

`real-worker-blocked.spec.ts` is a separate synthetic attempt to run an inert `return null` fixture through the real pinned PTC Workflow Host and Node worker. Its final attempted source SHA-256 is `8b98ac7495db71f8b56930da048baf0e92a2ff4e02cee99f6c89ed1fdd2ccfed`. Under the reviewed outer network-denying, profile-blocking macOS sandbox, the real PTC runtime's nested read-only Seatbelt application returned `sandbox_apply: Operation not permitted`; the tool reported `sandbox-unavailable` and the test failed. The script did not run. No fallback or weaker sandbox was used. Real worker execution and its successful cleanup remain unverified; this does not change the earlier fake-executor results.

The full failure log is retained outside the repository as `work/host-tests/utility-real-worker-v2.log` (SHA-256 `d8ca409103a144005f532956077d735100bae6c07eb2b22b3193a33c1e1368d8`) because it includes machine-specific absolute paths. The test uses only synthetic inputs, a fixture-owned temporary directory and synthetic parent/provider. It awaits workflow/context cleanup in `finally`, but that is not evidence of a successful real-worker cleanup. The fixture is research material, not a passing test, and must not be used as a reason to relax sandbox restrictions.
