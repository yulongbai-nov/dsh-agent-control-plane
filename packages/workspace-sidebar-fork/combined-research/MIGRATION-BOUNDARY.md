# Storage generation and migration boundary — proposal, not implemented

The requested new ordered generation is feasible only under an enforceable writer boundary. A format header or flock is advisory to a legacy binary: the source-backed two-process test shows that an old JSONL writer successfully commits while an unrelated corpus lock is held. On the same user identity, a process that can directly modify the new root can bypass a journal or marker; detecting every concurrent file mutation after the fact is not equivalent to preventing one. Thus the current shared-root format cannot safely assert that all mutations enter an authority. Enabling ordered mode must fail closed unless the deployment supplies and verifies a boundary that excludes old and uncooperative writers from direct access. This is a requirement, not a claim that a same-user local service by itself provides isolation.

A potential contract after that boundary exists:

- Require a clean source freeze: stop/fence all old writers; request each to flush and close, or explicitly acknowledge discarded pending state. Confirm no source writes while exporting. The 3/3 JSONL source-backed test includes a child killed before flush: its pending create is absent from another process both before and after crash. A filesystem-only export cannot recover that process-local state. Preserve the old tree and write an immutable export manifest of source identities, versions, validation results and hashes into a separate synthetic/test destination; fail closed on any unreadable or changing file. No actual user migration has been performed.
- Import into a new independently protected store with a new format identifier, schema version and fresh random epoch. Legacy roots remain untouched. A single authority or strictly cooperative writers must atomically commit durable rows, catalog revision and journal records under one cross-process transaction/lock; all producers, including external persistence, migrations, cold-cache changes and live session projections, must enter that ordering domain. If a filesystem implementation is used, specify and test durable publication, directory sync, torn writes, corruption, reboot and lock ownership; a lock alone does not fence noncooperative writers.
- Bootstrap from a coherent imported cut. Serve authorized snapshot and contiguous deltas under distinct access generations; drop and fence prior frames on changes. Format/version mismatch, unknown writer, missing epoch/journal, corruption, gap, overflow or lack of fencing must make the new authority unavailable, without silently falling back to the legacy root. Define how such violations can actually be detected; a watcher alone is insufficient.
- Rollback cannot silently merge histories. Before cutover retain a verified read-only old snapshot. Once new writes are accepted, rolling back requires quiescence and a separately tested lossless export/import that accounts for every accepted new-generation write; if conversion fails or an unrepresentable field exists, block rollback and keep both stores. Test pre-commit and post-commit crash points, migration restart, partial import, duplicate session IDs, access-generation races, and rollback after divergent writes. Secure backups and trust/authorization of the isolation service are separate necessary design work.

`jsonl-cross-process.test.patch` tests current legacy behavior, not this new design. The child and parent use synthetic roots and process barriers. One test verifies the worker runs as a thread in the direct child process, sends SIGKILL to that still-owned child, waits for it and checks the session remains absent. It does not establish crash consistency of a future journal. The local sandbox forbade `ps`, so the test makes no claim about unrelated or unknown descendants; independent process-inventory verification was unavailable. No contract extension, migration, new authority, crash-safe journal or compatibility implementation is claimed.
