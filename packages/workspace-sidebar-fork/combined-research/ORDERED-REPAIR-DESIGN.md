# Ordered list repair: design proposal, not implemented

The existing `session/list` RPC and `$events` notifications carry no demonstrated shared cut. A client cannot infer that a response includes an event received before or during the request. In particular, preserving only in-flight mutations cannot establish whether a later baseline is stale. The exploratory two-refresh fix is reverted; no bounded latency is promised.

A possible replacement is a versioned, principal-scoped catalog stream with these properties:

1. The Host owns a single serialized catalog authority. Every visible add, update, removal, and relevant projection replacement commits at a monotonically increasing sequence within an opaque Host epoch. All mutations and their projection values used by this feature participate in that authority. An event emitted by unrelated code is not itself proof of a commit.
2. A client subscribes before requesting a snapshot. The stream reports its epoch and contiguous sequence; the Host atomically captures a complete snapshot and its cut sequence under the same authority. The snapshot is filtered under a specific opaque authorization generation, as are deltas. The client buffers stream deltas and installs the snapshot only when epoch and authorization generation match, then applies every contiguous delta strictly after its cut in sequence order. A delta includes sufficient authorized data to reconstruct state, including removal; gaps, buffer overflow, epoch changes, or malformed payload discard the incomplete view and trigger one bounded resubscription, not speculative merging.
3. Revocation changes the authorization generation. Before publishing that change, the Host invalidates outstanding snapshots and queued deltas for the former generation. The client synchronously withdraws the old view and fences every in-flight request using connection epoch, authorization generation and local request identity; late responses cannot repopulate state. A new snapshot is scoped under the new grants. The protocol must prevent an old authorized frame queued in any transport layer from being delivered as a new-generation frame.
4. Catalog sequence gaps caused by filtering cannot be interpreted as dropped frames. Either deliver a per-principal contiguous sequence allocated after filtering, or send explicit non-sensitive sequence-advance markers for hidden changes. The latter still leaks that some change occurred, so its side channel needs review. Per-principal delivery also needs bounded lifetime and cache invalidation semantics.
5. Bound pending bytes, retries and subscriptions; on failure expose a recoverable error with a manual retry. A failed pull must not erase a newer proven add; a stale pull must not restore a revoked row. Coalescing cannot silently discard events during a second pull. Explicitly define snapshot inclusion of projections, sources that do not currently pass through the catalog authority, child and parent authorization, reconnect, process restart, and slow/offline clients.

A synthetic acceptance test should pause snapshot capture and delivery independently, commit add then remove, revoke access between capture and delivery, and deliver the old snapshot and old event late; assert that no stale label or removed row returns. Repeat with reordered transport delivery, duplicate events, a dropped delta, filtered non-owner changes, bounded overflow, and owner/guest projection restoration. A model of this proposal would only test protocol logic; it would not establish that current Host source has the required atomic authority. Production feasibility requires an audit of every producer and transport queue, implementation in the real Host/client, compatibility/version negotiation, and end-to-end tests. No such proof exists in this snapshot.
