# Source audit and minimal authority boundary

Audit applies to the combined WIP checkout at upstream `b830ec950faba0a46dda564be3e2d854afed94f1`; line references below name source paths within that checkout. It does not establish the installed app's behavior.

- `packages/api/session-controller/src/index.ts:193` emits list notifications from independently occurring `session/created`, `session/disposed`, `agent/created`, `agent/disposed`, `agent/status`, and selected `session/event` callbacks. `api/remotes/src/index.ts:49` captures those in a separate event queue and, in this WIP, strips all projection hints from `added`.
- `packages/session-query/session-query/src/corpus.ts:62` awaits persistence listing, then iterates the current live registry and merges the two sources. This is not an atomic live-plus-persisted snapshot. `api/session-controller/src/list.ts:131` then loops over those records and yields to the scheduler while reading live/cold projections. The individual session projection `asOfSeq` identifies a session's log position, not a global catalog revision. `list.ts:293` uses a separate persisted projection cache for cold rows, so even catalog membership and metadata lack a demonstrated common cut.
- `api/session-controller/src/control.ts:21` separately broadcasts projection changes through control queues and snapshots live sessions. `api/gateway/src/index.ts:599` filters and queues forwarded notifications per client, independently of the list RPC and control queues. `api/session-controller/src/index.ts:278` filters the completed list after its asynchronous construction. There is no demonstrated shared epoch, catalog sequence, or atomic access-generation cut across those paths.
- `api/session-controller/src/client/sessions/manager.ts:413` starts a fresh mutation journal for each list request; `:602` records events only while that request is in flight. A new add delivered before a refresh starts is not in that refresh's journal. A stale empty list result can replace the row; `evidence/r7-auto-refresh-wip.log` records a scoped failure from a reverted prototype. Existing list reconciliation may also be affected by assumptions about the persistence snapshot and projection-cache freshness; no general ordering proof is implied.

A minimal *architectural* change, not a safe patch to the current RPC alone, is a versioned catalog authority fed by every membership, status, activity and displayed projection producer, including persistence/cache lifecycle changes. It must own or atomically materialize a coherent catalog view, serialize commits and cuts, and expose an ordered principal-filtered snapshot/delta stream with explicit epoch and authorization generation. If cold persistence cannot supply a transactional cut with the live registry, the Host must first reconcile it into the authority and define its freshness contract; merely assigning a counter before or after the current asynchronous list would be unsound. It must define ownership for concurrent external persistence writers, cache invalidation, missed producer events, restart, sequence overflow, per-principal filtering and queues already holding old-generation frames. Otherwise reset/refetch and reauthorization cannot be proven.

`catalog-prototype.mjs` and `catalog-prototype.test.mjs` are a small standalone, synchronous, in-memory authority/consumer sketch with deliberately synthetic rows. Four race and failure tests pass in `evidence/catalog-prototype.log`. It assumes all mutations enter one authority, one synthetic epoch and global revocation; it has no DSH producers, async persistence, multi-principal filtering, real queue, wire codec, generation negotiation or network. It is nondeployable and cannot prove the real system has atomic ordering or confidentiality.

## Source-backed reproduction and concrete seams

Two tests added to the pinned `packages/session-query/session-query/tests/session-query.spec.ts` use its existing in-memory synthetic persistence backend and actual `SessionQueryEngine` / `SessionCorpus`. A persisted-only `SessionPersistence.create` changes the subsequent list without any `session/created` callback. In a controlled interleaving, the persistence test backend returns an old record, removes it, and creates a new live session before the corpus scans live state; the actual query returns both rows although those two sources did not coexist at the induced point. Both tests pass in `evidence/corpus-authority-gap.log` (43 other cases intentionally filtered out). This establishes permitted gaps in this fixture and contract, not proof that the installed backend experienced them. Test-only zero-context `corpus-authority-gap.test.patch` SHA-256 `0452198cdb0e08bbfe300312f605a6ce36de8fced271960517409fe24125723f` applies against the pinned source.

Concrete required interfaces before a correct Host/client prototype can be wired:

1. Extend `SessionPersistence` (`packages/session/session-persistence/src/index.ts:137`) and each relevant implementation to provide a transactionally coherent, service-wide durable membership/version observation plus a way to detect changes from other writers. Its present `stat` revision is expressly comparable only for the same session and service, and `list` has no corpus revision. `SessionCorpus.listSessions` must be able to align this observation with an explicit live-registry barrier, or the catalog authority must own a reconciled view with a documented bootstrap/rescan barrier and external-writer behavior.
2. Add catalog-authority ingestion for `session/created`, `session/disposed`, both agent lifecycle notifications, `agent/status`, user-message activity (`api/session-controller/src/index.ts:193`), all projection registry changes (`control.ts:21`) and cold-cache/persistence lifecycle or invalidation. Audit independently registered projections and any session header, cache, migration, persistence service replacement or external write that can change `list.ts` output. No existing single callback admits that complete set.
3. Make list snapshots and subsequent deltas come from that authority using a common epoch/cut and a bounded replay buffer; per-session `asOfSeq` cannot order catalog membership. Integrate access generation at the authority and Gateway queue boundary, not only on later client receipt. Decide how authorization invalidation and old queued frames are sequenced, and how invisible events affect per-principal contiguous sequences.
4. Introduce a negotiated protocol and client store reconciler, test gaps/overflow/epoch restarts, snapshot requests racing add/remove, stale projection/cache reads, connection loss and policy invalidation; verify queue boundaries and transaction semantics using actual Host, Gateway and persistence implementations. Existing standalone sketches do none of this and must not be ported as production code.
