This is nondeployable research against the isolated pinned public upstream checkout `b830ec950faba0a46dda564be3e2d854afed94f1`, not a DSH plugin registration or E2E test. The generated fixture, primitive bundle, and metafile are retained in the task workspace and are not committed. `fixture.cjs` (SHA-256 `42ced057762a2f2e98aa9ee866f738b487512e877f86838edb75272b2617300f`) injects local Acorn 8.18.0 into the actual `workflow-topology` parser and `workflow-board-projection` reducer. ## Manual preview review

The reviewed successor `manual-preview-reviewed.patch` SHA-256 `a8a835afa9833ecfaa66dddfab14b1d230d0399fe29972472fa7dba467886d01` applies to the clean pinned source; earlier candidate patches are retained unchanged. The embedded board previously stayed English under a Chinese panel: the candidate now derives its board language from the panel dictionary, with a new Chinese jsdom regression. Unexpected parser/layout exceptions now clear the graph and show a generic localized error; the text limit remains 100,000 UTF-16 code units. Native tests passed 42/42 and incremental TS6/targeted bundle build passed; latest bundle SHA-256 `2acad2d499aefd98dd22da719368ded71a3b4b8cb621ba68c85122218fddfe85`. Earlier embedded test hashes above describe earlier versions; the current browser harness SHA-256 is `1ed8f542fa2fb9397e7be200bdad5826ed633b9f09eaa8913cf1981cf6f00b84`.

Real Chromium synthetic tests passed for a 100,000-unit comment, 100,000 semicolons, 5,000 nested parentheses, an empty input error, a visible `maxlength`, ordinary parse, graph keyboard selection, edit/run/session clearing, and source containing `fetch`, `eval` and a global assignment that never ran. No page requests were observed. Observed total fill-and-preview times for one run were 36 ms and 75 ms respectively for the comment and dense-semicolon samples; these are not latency bounds or adversarial resource-safety proof. Deep nesting was handled as incomplete rather than crashing the component. Source inspection found no explicit `eval(` or `new Function` execution in the copied parser/topology/board inputs, but this plus the synthetic probes does not establish a formal no-execution guarantee for all browser or library behavior. Parser and layout run synchronously on the UI thread; 100,000 units can still cause resource exhaustion or jank, and browser heap/AST allocation is not bounded by the script-length limit. A production path needs a dedicated cancellable worker, hard memory/time limits, adversarial testing, parser supply-chain/semantic review and design for loss of the worker.

No async preview task is launched by this WIP: computation occurs synchronously from the click handler. Its local state is invalidated on edit/close and remounted by `(sessionId,node.id)` changes, as exercised in Chromium; JS memory is not securely erased. The manual input and notice have native bilingual accessible labels; React graph uses its selected English/Chinese language and native SVG keyboard selection. This is not screen-reader, focus-order, contrast, or full localization certification. A genuine Host source adapter, authorization, provenance, production staging and E2E remain absent. Logs are local evidence only and may contain workspace paths.

## Disposable preview Worker candidate

`manual-worker-candidate.patch` SHA-256 `5e9850576c3e4be1d1fc1229217f29e4cd4fe32cdb13221efc0c855c69d6f707` is a new pinned-baseline, zero-context research patch; the earlier synchronous patches remain historical. This candidate uses the pinned upstream Excel preview's tsdown/Rolldown embedded-worker pattern. Build-time bundling rejects more than one output chunk or external imports and embeds the Acorn MIT notice. The worker consumes one explicitly pasted string, parses and lays it out without executing the input, and returns a static unverified board. It terminates and revokes its blob URL on completion, error, cancellation, edit, close, unmount, run/session remount, or a nominal 2,000 ms timer. An identity check rejects stale replies; there is no fallback to synchronous parsing if worker creation fails. Input is limited to 100,000 UTF-16 units. Worker source and license remain research inputs in the patch.

Incremental TS6 plus targeted tsdown passed; `lib/client.js` SHA-256 `0ae51765de3921e12733d89c6d5942b8427296ed67f76cb220d5d5f0dda0ad9e`; native UI tests passed 42/42 (`evidence/manual-worker-native.log`, jsdom uses a fake Worker). `embedded.integration.cjs` SHA-256 `bd07fae4c4c7a13b27bd5d09e22440c8843529efd5c8e32d5e756be288e770e2` passed in actual Chromium with a real Worker for normal, 100,000-unit comment and dense source, deep nesting, edit cancellation and no execution of synthetic fetch/eval/assignment text. The test observed no page requests. A deliberately fake Worker separately checked timeout, explicit Cancel, a saved late reply after edit/run change, and constructor failure; these do not establish real CSP behavior. The test checked every tracked actual Worker was terminated after normal/edit cases. One run measured 75 ms and 120 ms for comment and dense fill-plus-preview; neither is a worst-case bound. Evidence is local at `../evidence/manual-worker-browser.log` and can contain workspace paths.

This is still **not a hard resource sandbox or deployment-ready security boundary**. A browser Worker is not a separate OS-level memory quota; the 2-second JavaScript timer can itself be delayed by a busy main thread and cannot prevent peak worker memory exhaustion. The worker has browser capabilities; no proof of a Worker-specific network deny policy or deployed shell CSP compatibility exists. A page-request route and disabled background networking do not establish process-wide network isolation. Worker failure shows an error rather than running the parser on the UI thread, but the synthetic constructor-failure case does not test actual CSP. Host source selection, authorization, provenance, installed shell integration, accessibility and screen-reader verification, stronger resource and supply-chain review, and real E2E remain open. `research-workflow-board.mjs` still must be staged beside emitted TypeScript before tsdown; the Worker-specific topology/Acorn sources are bundled directly from `src` by the new config. No personal data, profile or installed app is modified.
