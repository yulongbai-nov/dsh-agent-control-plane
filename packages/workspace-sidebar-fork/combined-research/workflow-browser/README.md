## Embedded native panel candidate

The native slot injector does **not** provide that prop; nothing registers this candidate or makes it visible in a real DSH session. With no prop, the native UI is unchanged. When supplied synthetically, the boundary forces the board source unverified, run status unknown, clears runtime node status, events and unmatched records, and offers no child navigation. The caller supplies static topology; this is not provenance, authorization or a live event integration. Locale is hardcoded English for this research seam and needs real product wiring.

## Unknown-source fallback and authority finding

Pinned native `WorkflowRunChatData` carries run name, status and phase/member summaries, but no script or authoritative tool-call/accepted-engine source link. The process-local terminal receipt research does not prove the guest consumed that source or bind an attempt to a run. An untrusted name, matching time, result, user-supplied call ID, or session ID cannot establish provenance or authorize reading another session. No Host-to-client source adapter was introduced. The native panel candidate instead renders a localized `role=status` source-unverified notice, while continuing to show native event-derived member statuses and retaining native navigation rules. The optional synthetic research board is still forced unverified/unknown and does not initiate source reads or expose board child navigation.

The expanded `unknown-source-candidate.patch` SHA-256 `7979c07f1bf45fd24c137c4d871b51f382e484daeeaea92d9d31c2656856d04f` includes the embedded candidate, bilingual notice, CSS, and a synthetic test; verify against the pinned checkout with `git apply --unidiff-zero --check`. It supersedes the earlier experimental patch only in this working evidence directory; no existing patch was overwritten. `workflow-run.client.spec.tsx` plus `panel-styles.client.spec.ts` passed 41/41: the added test supplies a forged `verified` board, checks unknown notice, disabled board navigation, no supplied event display, no `fetch` and no navigation callback. This is a no-call assertion in a synthetic fixture, not proof of Host authorization. The first added test had an overbroad status selector (not a product defect); the corrected run and earlier log are retained locally.

After the notice change, incremental TS6 build and targeted tsdown passed; bundle SHA-256 `f8d5e2ebf2e6166de8edd79057d0e915d3e3bdabe5b928e68164e2dabce18007`. `embedded.integration.cjs` SHA-256 `4ca39a78e0da59fe36befe386efa1bdeeaea5a7763f21131903f3f582bd110ec` passed in Chromium with pinned primitives: English notice, native no-prop behavior and direct-parent callback, forced unverified board, no page requests, and no page errors.
