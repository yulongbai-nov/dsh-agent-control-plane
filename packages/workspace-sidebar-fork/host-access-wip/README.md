# WIP: versioned host/client catalog-access experiment

**Not installable and not a complete privacy boundary.** `catalog-access.patch` is a candidate against public DeepSeek Harness source commit `b830ec950faba0a46dda564be3e2d854afed94f1`; it is not an installed-app patch, a product build, or proof that this public source matches the installed rc.5. Use only a disposable synthetic checkout with reviewed dependencies. Do not apply it to the installed application or a real profile.

A synthetic non-owner Gateway test against this public source showed that a parent `session/projections` grant disclosed its denied child's catalog ID, label, mode and creation time while direct child `session/projections` was denied. A characterization assertion passed and a privacy assertion failed. No real sessions, installed DSH app, or network were used.

## Candidate behavior and protocol boundary

The original `session/control` wire type has only `baseline` and `projection`. Existing client metadata rejects a new `access-reset` frame, so adding it to that endpoint would be a wire-breaking change. The candidate instead preserves `session/control` as V1: owner calls retain native behavior; for non-owners, catalog values and catalog update frames are suppressed, even when a child is otherwise allowed. Other permitted V1 projections remain available. This deliberately degrades legacy non-owner catalog visibility.

The candidate adds a distinct `session/controlV2` stream. Non-owner callers need an explicit **global V2 action grant and separate per-Session V2 grants**; existing `session/control` grants do not imply V2 access. V2 filters each parent catalog by same-action child Session grants. The stream follows the peer's Remote access changes and emits `access-reset` with a new filtered baseline after policy invalidation; its matching candidate client aborts pending projection reads, clears old values/watermarks, and reseeds with the original observed Session sequence. It does not invent event seqs. The candidate client requests V2 only: an old Host with no V2 endpoint fails rather than silently falling back. The existing package version remains unchanged in this WIP, so any future release needs explicit coordinated Host/client versioning and migration; endpoint naming alone is not a deployable release plan.

For parent `session/projections`, denied child catalog entries are filtered. Parent `session/page` and `session/follow` fail closed on a page or frame containing a denied `subagent/catalog` event, rather than dropping records and silently breaking contiguous sequence semantics. Owners keep their original behavior. A separately authorized child with a correct direct-parent address still opens even when the parent itself is not granted; incorrect parent/mode remains rejected.

**Remaining blockers:** `remoteAccess` bypasses checks for owner/trusted in-process callers and is not a local collection authorization contract. Other event types, arbitrary messages, projections, or `SessionSummary.parentSessionId` may contain related identifiers; this patch does not classify them. Cross-workspace identity/ownership is not established. A policy must call `remoteAccess.invalidate()` for changes; delivery and already-in-flight history/list results across revocation are not fully fenced, and prior disclosure cannot be undone. Legacy clients can obtain previously allowed catalogs through other paths and cannot receive V2 resets. Denying a parent history can impair continuity and usability. Old Host/new client terminal failure behavior and full application lifecycle require actual integration testing. These limitations rule out a production privacy or R7 E2E claim.

## Reproduction and evidence

1. Obtain a **fresh, separate** public-source checkout at the full commit above. Verify its HEAD and target files, and prepare reviewed compatible build dependencies separately. No dependency installation is included here.
2. Run `git apply --unidiff-zero --check` on `catalog-access.patch` against that checkout, review the diff, and apply only to the disposable checkout. The patch uses zero context and must also be applied with `git apply --unidiff-zero` to that exact commit. The pinned public checkout accepted the check. Never apply to the installed app.
3. With reviewed Node 24/Vitest and a dedicated synthetic `HOME`/`TMPDIR`, run `packages/api/session-controller/tests/remote-access.host.spec.ts`, `r7-synthetic-catalog-mitigation.host.spec.ts`, and `r7-access-reset.client.spec.ts`. The latter two are included by the patch. The observed result was **19/19 synthetic tests passing**: 7 upstream access tests plus 12 candidate Host/client checks. These cover denied/allowed child, parent grants, owner and duplicates, Gateway V2 grant gating, legacy catalog suppression, revocation/regrant resets, same-seq cache reset, stale projection-response fencing, wrong direct parent, and new-client/no-V2 no-fallback.
4. Strict TypeScript 6.0.3 Host and Client project-reference builds passed after regenerating the package's Typert Host and Remote-client artifacts from the modified source. `codec-compat.test.mjs` separately checks public-source generated artifacts: old Host/client have no V2, old/new legacy codecs reject `access-reset`, and new V2 Host/client codecs accept it and reject unknown frames. Supply explicit `OLD_HOST`, `OLD_CLIENT`, `NEW_HOST`, and `NEW_CLIENT` absolute paths to generated **public-source build** artifacts; no installed app paths. The observed codec check passed **1/1**.
To regenerate the synthetic candidate artifacts from the root of the prepared checkout, the observed order was:

```sh
node node_modules/typescript/bin/tsc -b packages/api/session-controller/tsconfig.host.json --force --pretty false
node --import tsx --input-type=module -e "import {WorkspaceTypertGenerator,writePackageArtifacts} from './packages/typert/generator/src/index.ts';const root=process.cwd();const artifacts=new WorkspaceTypertGenerator(root,{checkDiagnostics:false,rejectBuildOutputs:true}).generate(['@deepseek-ai/dsh-api-session-controller'],['host']);if(artifacts.length!==1)throw Error('unexpected artifact count');writePackageArtifacts(root+'/packages/api/session-controller',artifacts);"
node node_modules/typescript/bin/tsc -b packages/api/session-controller/tsconfig.client.json --force --pretty false
```

The generator writes `lib/typert.host.*` and `lib/typert.remote-client.*` in the disposable checkout. The selected Host/client build artifacts are local verification outputs, not a published package, and must not be copied into the installed app. Both compilers require the separately prepared build dependencies and run only after reviewing the target and ensuring it is disposable.

5. The assembled `client-apply.client.spec.ts` attempt was **blocked**, not passed: the prepared source checkout could not resolve the `@deepseek-ai/dsh-web-app` test dependency. Full UI, Host/client mixed-version lifecycle, policy deployment, and E2E remain unverified.
