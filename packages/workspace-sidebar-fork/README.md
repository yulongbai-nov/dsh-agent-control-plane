# Experimental workspace sidebar source candidate — not installable

This is an initial R7 source integration candidate, **not a completed fork, package, deployment, or E2E pass**. Do not install it in a DSH profile. `upstream/src` is the complete 28-file `ui-workspace/src` tree from public commit `b830ec950faba0a46dda564be3e2d854afed94f1`; `upstream/manifest.json` pins Git blob identities and lengths and `upstream/LICENSE` retains the upstream MIT notice. `candidate-src` is a copy with the experimental changes; compare the directories for the exact source delta. The public source commit and the locally installed rc.5 asset are **not yet proved equivalent**.

The candidate wraps each *already selected* native root in `LineageGraft`, adds an optional toggle inside the existing `SessionNodeItem`, and uses the shared `session-tree/lineage.mjs` projection. It wires explicit expansion to `sessions.refreshProjections` and opens visible child rows with the direct-parent address. Grouped and flat views are patched; the search renderer, original tree derivation, native watermarks and root keys are unchanged. Expansion does not request children until the user opens a root; closing a root discards descendant expansion state. This is a narrow synthetic prototype, not evidence that upstream native behavior or host authorization is preserved.

## Blocking gaps

- The upstream pnpm workspace manifest, lockfile and selected compiler/build manifests are preserved in `upstream/build-metadata` and checked against exact Git blob IDs. The actual workspace sources and dependency/build closure are absent; the candidate has **not been type-checked or built** with upstream's complete toolchain. The lockfile pins pnpm 11.28.5, TypeScript 6.0.3, tsdown 0.22.2, lightningcss 1.33.0 and Vitest 4.1.11. Following all workspace links, including dev and optional dependencies, visits 296 importers; this is a graph upper bound, not a minimal build closure. The available pnpm is 11.25.0; the exact TypeScript 6.0.3 tarball was found in the local npm cache, verified against lockfile SHA-512, and installed offline without scripts into a separate work directory. The exact pnpm, tsdown, lightningcss and Vitest tarball keys were not found in that npm cache. An experimental explicit JS staging transform is described below; it has not been integrated into or verified with the actual upstream build.
- A strict TypeScript 6.0.3 diagnostic of the graft using intentionally narrow test stubs passed; an earlier TS7 diagnostic found and fixed unchecked array access. These stubs are not the real upstream types and cannot prove the candidate builds. The verified TypeScript 6.0.3 `--noCheck --noResolve` also transpiled only the graft for a synthetic browser experiment, not a production build. Run `TSC_ENTRY=<typescript-6.0.3-package>/bin/tsc R7_TYPECHECK_BASE=<existing-writable-directory> node packages/workspace-sidebar-fork/test/typecheck-graft.cjs`; the diagnostic retains its isolated fixture directory. It verifies the complete 140-file compiler package by SHA-256 before executing it and rejects missing, extra, altered, or symlinked files. The checked manifest `test/typescript-6.0.3-files.json` has SHA-256 `b0e8e509a0906d501c032340bf172321ff4079121b67c4bb17ae1f47eb5a04bc`; its file hashes were generated from the cached TypeScript tarball after verifying the lockfile's integrity `sha512-y2TvuxSZPDyQakkFRPZHKFm+KKVqIisdg9/CZwm9ftvKXLP8NRWj38/ODjNbr43SsoXqNuAisEf1GdCxqWcdBw==`.
- Root lists supplied to the shared projection are scoped to each native group; cross-workspace identity, host-enforced authorization, incomplete catalogs, stale refresh and ownership boundaries require a design and real tests before enablement. Never treat a string, projection, or this code as an authorization proof.
- Native accessibility/tree semantics, keyboard focus and recovery, touch and drag behavior, statuses/avatars, localized errors, screen readers, subscription lifecycle, multiple simultaneous requests and animated row interactions need full integration work. Child `role=treeitem` elements are currently siblings under a separate group rather than nested inside the native parent treeitem. The candidate is not accessible-feature complete.
- Search remains native and does not search lineage children; catalog loading and per-level errors are rudimentary. Real Host transport, persistence, concurrency, package installation, rollback and visual behavior are all unverified.

## Current tests

`node --test packages/workspace-sidebar-fork/test/*.integration.mjs` checks the shared projection adapter and verifies the pinned source blobs, plus static equality of native search, list derivation and watermark functions. These assertions do not prove native behavior.

`LOCK_YAML_MODULE=<reviewed-js-yaml-module> node packages/workspace-sidebar-fork/test/lock-closure.cjs` inventories reachable `link:` importers in the exact pinned lockfile. This read-only count includes dev/optional links and does not install packages or resolve external artifacts.

`upstream/ts-project-graph.json` and `ts-project-shas.json` preserve 127 recursively referenced upstream compiler configs and Git blob IDs. `TSC_ENTRY=<verified-ts6-package>/bin/tsc node packages/workspace-sidebar-fork/test/check-ts-project-graph.cjs` checks their 834 declared edges against the TS6 JSONC parser. The staged source has one of the 121 referenced workspace importers; `upstream/build-closure-audit.json` lists the remaining 120 and exact direct external pins, including dev/test and optional entries. The separate `upstream/build-tools-audit.json` inventories pinned snapshots reachable from selected build/typecheck seeds on darwin-arm64. Its npm-cache results record one local observation for exact standard URLs, not proof that every other cache or full transitive dependency closure was searched.

The source candidate imports JavaScript modules that the upstream TypeScript configuration does not itself emit. `staging/stage-lineage.cjs` is a **prototype** for adding them beside a separately emitted `client/rows/LineageGraft.js`: set `TSC_ENTRY` to verified TS6 and `R7_EMIT_DIR` to the emitted tree root. It checks pinned source hashes and compares the emitted graft with TS6 transpilation, then writes `lineage-plan.mjs` and `shared-lineage.mjs` with one verified relative-import rewrite. Existing targets are refused. Any source update requires review and updating the pins; source maps and actual tsdown integration are not verified. The transform can partially create files if an unexpected filesystem error occurs between writes; use only a fresh test output. Run `TSC_ENTRY=<verified-ts6-package>/bin/tsc R7_STAGE_TEST_BASE=<existing-writable-directory> node packages/workspace-sidebar-fork/test/stage-lineage.integration.cjs` for deterministic output, import behavior and source/emitted drift rejection tests; fixtures are retained.

To independently regenerate the pinned compiler inventory from a local tarball, run `python3 packages/workspace-sidebar-fork/test/generate-ts6-manifest.py <typescript-6.0.3.tgz>` and compare its output with `test/typescript-6.0.3-files.json`. The script checks the upstream SHA-512 before inspecting the archive and does not extract it.

`test/graft-browser.integration.cjs` is opt-in: it uses the same `PLAYWRIGHT_PATH`, `REACT_BUNDLE_PATH` and `CHROMIUM_PATH` variables as the session-tree browser regression, plus `GRAFT_COMPILED_PATH` pointing to a locally transpiled `LineageGraft.js`. It checks real rc.5 production React and Chromium against a **synthetic** native row and Host, including lazy refresh, propagation, direct-parent navigation and collapse. The script rejects a nonmatching React asset hash. It is not the real WorkspaceBrowser, native DSH GUI, or installation test.
