# 真实 GUI 测试的隔离替代环境：只读调查

## 结论

本次**没有确认任何现成可用且安全隔离的 VM、专用低权限身份或真实浏览器控制方式**。这不等于证明它们不存在，也不等于证明真实 GUI E2E 不可能。未启动 DSH、GUI、浏览器、VM、模型或服务，未运行 GUI E2E，也没有通过安全隔离验收。既有 GUI 沙盒的局限及先前反例见 [README](README.md#只读调研结论和必须避免的命令)；本次没有重复那些主动探针。

调查以只读观察为限，不创建账户、安装软件、变更配置或权限，不访问用户数据、配置、Keychain 或凭据，也不发起网络请求或监听。发现路径策略拒绝后停止进一步探查；没有用其他工具或路径重试受拒绝的目标。

## 继续之前最小需要什么

1. **先由用户选择并明确授权隔离承载环境**：优先指定一个已存在、允许本任务使用的专用 VM（包括谁提供及其管理接口）；若没有，用户需决定是否另行授权创建 VM 或专用低权限账号、准备系统和工具。当前任务不创建、不安装、不修改配置。仅有虚拟化框架或管理员身份不足以作为承载环境。
2. **由用户指定可审查的官方浏览器控制入口，或授权准备测试用浏览器工具**。若需要在隔离环境里安装或启用任何东西，须先单独明确授权；本次既未安装，也未证实官方 seam 不存在。对于本次 `PATH_RESTRICTED` 的安装目录，须由有权限的人提供可访问的官方文档或处理访问策略，不能自行绕过。
3. **在另行授权后先评审并验证安全边界，而不是直接启动 E2E**：环境仅含合成 fixture/凭据 canary，与真实用户文件、Keychain、会话和现有 GUI 分离；明确文件与 IPC 隔离、真实进程树继承、网络和监听所有权、浏览器连接目标、外部访问阻断，以及退出清理。正向对照和负向 canary 都需验证。若使用专用账号而非 VM，还需独立证明网络、IPC 和其他系统服务的隔离；低权限身份本身并不足够。

授权、准备与安全验证均未发生之前，继续保持 [README 的真实 E2E 门槛](README.md#进入真实-e2e-的门槛)为未完成，不连接已有 GUI，不把 mock 或只读盘点当作隔离验证。
