# Synthetic Host session permission experiment — nondeployable

Against public upstream `b830ec950faba0a46dda564be3e2d854afed94f1`, this fixture checks that an absent Remote invocation is denied before calling `remoteAccess.allows`, then checks a synthetic Session resource before opening and after reading a bounded synthetic handle. It closes the handle on success and revocation. The test uses real pinned RemoteAccess policy code with a deliberately constructed in-process invocation and a synthetic read-only source. A 1/1 targeted test passed, with 7 unrelated tests skipped, in an outer network-denying sandbox excluding personal profiles and the installed app. It did not invoke the real Gateway or a persistence backend. Retained external log `work/host-tests/telemetry-host-permission-v2.log` SHA-256 `658174571cc56f0ff007be7d976682b3d901574baf09e5dea7e396b6630de863`. Adapter SHA-256 `102b68a9654b1d5661a05a61aa297c14ccc5906100fd0dd47dbf7197e7bc981f`; test patch SHA-256 `ef2bff21c9195cb6f4104fb8ed08c07f12d97639bf9d9a448a06b414c73b753b`. Input hashes measured before and after the targeted run; full transitive dependencies not pinned independently.

**No production authorization is established.** The fixture's in-process context and source are forgeable. `principalOf` intentionally returns undefined for both owner and local calls, while `remoteAccess.allows` permits local calls; a non-undefined invocation alone cannot prove it came from the Gateway. The chosen `session/projections` permission is a test stand-in, not an approved telemetry collection, export, model disclosure, or deletion permission. Gateway admission binds the peer principal and checks endpoint/resource, but a deployable adapter must be registered through an authorized endpoint with appropriate dedicated actions, authoritative workspace and Session scope, distinct disclosure channels and revocation/TOCTOU rules. Never wire this fixture to real sessions, credentials, profiles, or a model.

SessionPersistence's read handle supplies an observed contiguous log slice and requires `close`; the per-session `stat` revision is not a durable global generation or authoritative cross-session cursor. The test's count is at most 100 observed fixture entries, not a total or durable attribution. Cross-source transactionality, source identity, cursor durability, consent, key handling, deletion semantics, and concurrent revocation remain unresolved.

For a disposable exact pinned checkout with dependencies already installed from the frozen lockfile, copy `session-adapter.ts` to `synthetic-telemetry-host-wip/session-adapter.ts`, apply `git apply --unidiff-zero --check permission-test.patch` and then apply it, and run the single `synthetic session adapter authorization characterization` test in `packages/api/session-controller/tests/remote-access.host.spec.ts` inside a network/profile-denying sandbox. The patch is test-only and is not a production plugin or E2E test.

## Dedicated Gateway fixture

`gateway-fixture.spec.ts` registers a synthetic `syntheticTelemetry/sample` endpoint in the real pinned Gateway, with separate fixture workspace, Session and disclosure-channel resources. Synthetic policies bind the caller and each resource; the test checks missing grant, wrong caller, workspace, Session and channel, denial for local/owner contexts lacking fixture authority, inconsistent workspace–Session mapping, and a revoke/regrant while a synthetic read is pending. A fixture-controlled monotonic revision fences that specific ABA case and the handle counter records closing. The reviewed network/profile-denying run passed 1/1; test SHA-256 `464a72844e9b9a740bc89b2b187c12f99f090be6f773c1238df99a26f78507df`, retained `work/host-tests/telemetry-gateway-v2.log` SHA-256 `3f4164760e2fccd6eb62292fef5f2df923b60e7337e7c1bc6a2401be06505165`. Place the file at `packages/api/gateway/tests/synthetic-telemetry-gateway.spec.ts` in the isolated pinned checkout to reproduce.

The fixture revision and policy are synthetic and manually updated together; upstream `remoteAccess.invalidate` does not expose that authoritative revision or serialize a later wire send with revocation. A final authorization recheck cannot prevent a revocation after the check or retract delivered data. The source, association mapping, caller and policies are test-owned, not actual Session persistence, authenticated product identity, workspace ownership, production telemetry grants, or proof of a corpus cursor. The owner is intentionally denied in this test because no fixture authority was provided; this is not a proposed owner product policy. No deployed endpoint or real data is involved. A production integration remains blocked on source authenticity/durability, dedicated channel grants and authoritative atomic revocation/delivery semantics.
