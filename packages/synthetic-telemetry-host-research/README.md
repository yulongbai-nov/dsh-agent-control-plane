# Synthetic Host session permission experiment — nondeployable

Against public upstream `b830ec950faba0a46dda564be3e2d854afed94f1`, this fixture checks that an absent Remote invocation is denied before calling `remoteAccess.allows`, then checks a synthetic Session resource before opening and after reading a bounded synthetic handle. It closes the handle on success and revocation. The test uses real pinned RemoteAccess policy code with a deliberately constructed in-process invocation and a synthetic read-only source. A 1/1 targeted test passed, with 7 unrelated tests skipped, in an outer network-denying sandbox that explicitly denied the installed app, `.dsh`, `.codex`, and the original DeepSeek Harness project paths. It does not establish denial of every possible personal profile path. It did not invoke the real Gateway or a persistence backend. Retained external log `work/host-tests/telemetry-host-permission-v2.log` SHA-256 `658174571cc56f0ff007be7d976682b3d901574baf09e5dea7e396b6630de863`. Adapter SHA-256 `102b68a9654b1d5661a05a61aa297c14ccc5906100fd0dd47dbf7197e7bc981f`; test patch SHA-256 `ef2bff21c9195cb6f4104fb8ed08c07f12d97639bf9d9a448a06b414c73b753b`. Input hashes measured before and after the targeted run; full transitive dependencies not pinned independently.

**No production authorization is established.** The fixture's in-process context and source are forgeable. `principalOf` intentionally returns undefined for both owner and local calls, while `remoteAccess.allows` permits local calls; a non-undefined invocation alone cannot prove it came from the Gateway. The chosen `session/projections` permission is a test stand-in, not an approved telemetry collection, export, model disclosure, or deletion permission. Gateway admission binds the peer principal and checks endpoint/resource, but a deployable adapter must be registered through an authorized endpoint with appropriate dedicated actions, authoritative workspace and Session scope, distinct disclosure channels and revocation/TOCTOU rules. Never wire this fixture to real sessions, credentials, profiles, or a model.

SessionPersistence's read handle supplies an observed contiguous log slice and requires `close`; the per-session `stat` revision is not a durable global generation or authoritative cross-session cursor. The test's count is at most 100 observed fixture entries, not a total or durable attribution. Cross-source transactionality, source identity, cursor durability, consent, key handling, deletion semantics, and concurrent revocation remain unresolved.

For a disposable exact pinned checkout with dependencies already installed from the frozen lockfile, copy `session-adapter.ts` to `synthetic-telemetry-host-wip/session-adapter.ts`, apply `git apply --unidiff-zero --check permission-test.patch` and then apply it, and run the single `synthetic session adapter authorization characterization` test in `packages/api/session-controller/tests/remote-access.host.spec.ts` inside a network/profile-denying sandbox. The patch is test-only and is not a production plugin or E2E test.

## Bounded numeric source adapter

`numeric-adapter.ts` is a separate synthetic-only reader, not wired to the Gateway endpoint. It reads at most 101 events to enforce a maximum of 100, accepts only a complete sequence of complete turns from offset zero, calls the actual pinned `deriveTurnTokenUsage` for each, and returns only `asOfSeq` and summed `outputTokens` with durability `unknown`. Missing/invalid usage, unsafe totals, gaps, incomplete turns, an exceeded read bound, storage failure or close failure return `unknown`; no message text, prompt, model name or other event data is returned. This conservative shape does not infer source generation, a durable cut, cross-store atomicity, or authorization.

`numeric-fixture.spec.ts` uses actual pinned JSONL SessionPersistence and token-meter fold with a synthetic six-event turn. It verifies output count 7, rejects a truncated bounded read, missing usage, malformed sequence/usage and close failure, and stores only the numeric result in the synthetic SQLite ledger. After close, it checks every remaining file in the fixture ledger directory for a synthetic plaintext sentinel and finds none, then reopens the row. The source JSONL intentionally contains the synthetic sentinel; checking current ledger files does not prove secure deletion, absence from transient memory, filesystem snapshots or all possible journal states. The test passed 1/1 under the same reviewed restricted sandbox. No real session, model, profile or E2E was used.

## Versioned Host API delivery boundary — blocked

No production or versioned telemetry API has been installed. The existing synthetic endpoint cannot establish the requested end-to-end revocation fence: the pinned Gateway admits the call before dispatch, awaits its method, closes its invocation, then returns or serializes the result; it does not re-check an authorization revision at the final transport boundary. `remoteAccess.invalidate()` notifies followers but exposes no durable monotonic epoch shared with Gateway delivery, workspace membership, JSONL and SQLite. A Session and Workspace being individually permitted does not by itself prove their durable association or establish an atomic membership revision; the earlier mapping was a fixture Map. The numeric adapter is separately synthetic and is not wired as a production-authorized collector.

`gateway-delivery-gap.spec.ts` uses actual pinned Gateway/RemoteAccess with synthetic principals and resources. It schedules a revocation in a microtask immediately after the endpoint's final check and before the direct Gateway `invoke` promise settles. The first in-flight call still returns the synthetic value while a subsequent call is denied. This demonstrates the controlled in-process check-to-return gap, **not** a live network disclosure or proof of transport behavior. The test passed 1/1 under the reviewed restricted sandbox; source SHA-256 `0c65deafb478cbcb2649486a316d6738514f2127d804a568995750dc095ef145`, external log `work/host-tests/telemetry-delivery-gap.log` SHA-256 `409ddca4a76bc531adb47ddaf925785393df88e1b7b0c8471a0edaf360860f7d`, identical pre/post source/Host manifest SHA-256 `9ed927f28bec4fd7e24912c8a9d58b0d1da3012d8b650a844f69e3435ad972f5`. This manifest does not cover every dependency.

Before a real API, a Host-owned identity and consent authority must bind exact principal, authoritative workspace–Session association and dedicated operation/channel grants to a versioned revision. The design must specify a supported delivery-time revalidation/linearization boundary and what revocation means for in-flight or already delivered data, plus source generation, durable cursor, cross-store commit/recovery and safe deletion. Without those contracts, unknown scope and unsettled writes remain UNKNOWN and no caller-supplied fixture token or local context may authorize real collection or disclosure.
