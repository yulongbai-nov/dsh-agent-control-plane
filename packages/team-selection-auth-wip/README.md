# Team member selection authorization — fail-closed WIP

**R3/R6 selection is not implemented or exposed.** This separate research patch targets public source commit `b830ec950faba0a46dda564be3e2d854afed94f1`, includes the earlier `team-selection-wip` source, and adds a fail-closed Host barrier. It is not an installed app/profile change, release, authorization policy, or real E2E result. Do not apply it together with the earlier selection or combined depth patch.

## Audit findings

- `packages/experimental/tool-agent-team/src/index.ts` installs Team tools in Agent scope, takes `exec.agent` as caller, and delegates to `agentTeams.spawnTeammate`; the Team roster checks exact live Agent membership and Lead role. This identifies the caller but does **not** itself authorize a model, reasoning effort, output-token override or preset for that Team.
- The pinned `tool-subagent` implements an opt-in per-Session model-selection policy: settings default off, exact provider/model allowlist is projected into Session state, explicit model/effort requests are validated, and the live LLM runtime preflights the route. After the asynchronous preflight it checks that the provider instance has not changed. Separately `SubagentPresetSelection` uses a deployment-owned allowed preset list and rejects backends without independent preset capability or with inherited parent context. These are source observations, not a grant to the Team tool: the policy and helpers are private implementation details in `dsh-tool-subagent`, not an exported shared Team authority, and whether its user-granted scope extends to Team or workflow is unproven. There is no established Team-scoped maxTokens permission, revocation epoch or atomic admission across these paths.
- The prior selection WIP validates a narrow options shape and native provider capabilities, but `TeamService.spawnTeammate` accepts direct Host calls, bypassing the model-facing subagent tool's policy. Backend capability or `llm.resolveCallConfig` alone is not user authorization. Publishing model/preset fields in `spawn_teammate` would therefore create an unproven permission bypass.

## What this WIP does

It keeps the model-facing Team tool schema unchanged and rejects any explicit `agentOptions` or `agentPreset` at the Team Host before journaling or starting a backend with `TEAM_SELECTION_UNAUTHORIZED`. Omitted choices retain the pinned inheritance path. It has no allow branch and no fake `authorized` flag; this is deliberate until a trusted scoped policy exists. Unsupported or unknown backend selection is rejected at this earlier barrier rather than being represented as a backend-capability result. This is a safety experiment, not R3/R6 completion.

Pinned-source Host tests: **50 passed, 2 expected failures**. The two expected failures are the prior WIP's desired authorized-route and selected-preset tests; they remain blocked because no authority exists. A synthetic actual scoped Team-tool schema test confirms that model/preset fields are absent, and Host tests verify explicit routes/presets and unsupported-backend overrides reject before roster provisioning/provider invocation. Existing Team tests for inherited behavior passed. The full pre-existing tool-agent-team test file was **not** run: its `@deepseek-ai/dsh-llm-deepseek` development package was absent from this prepared dependency closure; a separate narrower real Host schema fixture was used instead. Team source `tsc --noEmit` passed. No real provider/model, browser, user profile or network was intentionally used; an OS egress boundary was not established.

## What must precede exposure

1. Specify whether the user's existing subagent selection setting authorizes Team choices, or introduce a separately consented Team-scoped policy; distinguish trusted Host actor from untrusted model arguments and protect exact live caller identity.
2. Provide a shared Host-owned authority callable by **both** direct Team Host API and tool/other entrypoints, with durable per-scope policy, explicit route/preset/maxTokens grants and revocation. Unknown or missing policy denies explicit choices. Existing private helpers cannot simply be copied and treated as cross-entry authorization.
3. At admission capture policy/provider/preset identity and revision, perform compatible adapter/effort preflight, then revalidate identity, authorization epoch and cancellation at the actual creation boundary. A settings change during any await must fence unpublished creation. Define behavior for provider replacement, preset revision changes, cold recovery and external/provider-managed backends; unsupported capability fails rather than silently downgrading.
4. Prove direct Host, model tool, workflow and other relevant paths cannot bypass the authority, test deny/allow/revoke/races/restart against actual synthetic Host services and maintain legacy inherited/no-selection behavior. Nested Team depth ownership and real GUI/transport E2E remain separate blockers.
