# R5 archive admission — pinned native Host counterexample

**R5 remains unimplemented and the tested native behavior fails its explicit message-rejection requirement.** This directory contains a reproducible synthetic canary and a separate **nondeployable** partial source WIP, not a complete fix or E2E result. They target public source commit `b830ec950faba0a46dda564be3e2d854afed94f1`; the installed Host is not proven equivalent. No user profile, real Session, model, browser or running service was accessed.

## Concrete tested behavior

In an isolated Host composition, the test mounts the real pinned `WorkspaceRegistry`, `ArchivedSessionGate`, Team service, SubagentRuntime, AgentLoop and JSONL child persistence, plus a **memory-backed synthetic Workspace domain** and mock model adapter. It creates a Lead and child, invokes the real `archiveSession(child, {stopActivity:true})`, disposes and remounts the registry over the same in-memory domain, and verifies the child remains archived. It then drains the child and confirms it is nonresident. A Team message still returns an accepted message ID and cold-resumes the same child. The real archived pre-step gate rejects a proposed model step, but direct `subagents.sendMessage`, host queue and host steer also return accepted IDs while the child remains archived. An accepted ID is an admission receipt, not proof of model execution or durable inbox flush.

The test contains two cases: one passes by documenting the observed bypass; one uses `it.fails` for the desired rejection-before-acceptance contract. Output **1 passed, 1 expected fail**, not 2 feature passes. The Workspace remount retains an in-memory backend within the same process; it is not a disk or process restart test. JSONL fixtures are synthetic, created under a task-owned TMPDIR and deleted by test cleanup. The isolated Host test does not establish network isolation, complete race coverage or user-facing E2E behavior.

`archive-bypass-canary.patch` is a standalone test-only zero-context patch for the pinned public source (SHA-256 `6f07c01cd46c492cf9a8bf81717e7a2d29be0b30464a4c31132892c4232a7504`). `git apply --unidiff-zero --check` passed on the pinned base. Use it only in a fresh reviewed synthetic source copy, with explicit HOME/TMPDIR and mock model; do not install it in a profile. ## Owning paths and why a local check is not the fix

- `packages/workspace/workspace/src/index.ts:archiveSession` serializes **Workspace registry writes** via `enqueueOperation`; a normal archive checks activity before writing, while `stopActivity` writes archive first and then issues stop requests. `unarchiveSession` removes the stored flag. These operations do not serialize with subagent inbox admission.
- `packages/api/session-controller/src/archived-session-gate.ts` blocks `agent/pre-step` for an archived Session or live-resolved subagent ancestor. It is an execution gate, not a message-admission gate, and missing ancestors do not establish a full cold lineage.
- `packages/experimental/agent-team/src/index.ts:sendAdmitted` resolves Team membership; sends to a teammate route through `steerHostSubagentPrompt`, while sends to the Lead use `root.steer` directly. A child-only manager patch misses the Lead path.
- `packages/subagent/subagent/src/manager.ts` owns `sendMessage`, `queuePrompt`, `steerPrompt`, child locks, `deliverFollowup`, `coldResume`, `submitMaterialized` and `submitAdmitted`; other entrypoints may invoke Agent inbox methods directly. Its child lock is independent of the Workspace registry's write queue. A `workspaceRegistry.archivedSessionIds.includes()` check alone is a read/check/write race across an asynchronous archive or an unobserved writer, and a manager-only gate misses other inbox/Lead paths. Missing Workspace state or missing authority cannot safely be treated as unarchived.

## Required fix and evidence — not implemented

One trusted, versioned admission owner must serialize the durable archive/unarchive transition and **all** send, queue, steer, resume and relevant direct Agent-inbox paths, with exact caller and lineage authorization. It must define a single linearization point, persist an admission/version receipt, fence stale epochs at publication and fail closed on missing or conflicting state. A pending archive versus a send needs an explicit ordering contract: a send committed before archival differs from one accepted after it; do not silently erase an already accepted message. Force archive's stop requests, user-visible archive state, in-flight work and unknown/failed durable writes need a documented recovery state machine. Multiple processes require durable fencing/CAS or a proven single owner; an in-memory mutex or a separate model does not suffice. Restore must commit before cold-resume admission and preserve the same Session ID.

The pinned source does not supply the demonstrated common durable owner or authoritative nested Team lineage needed to implement this without bypasses or changing non-Team behavior. The partial source experiment below is not presented as a complete fix. Before claiming R5, add real synthetic Host tests for every entrypoint and Lead path, inactive/running targets, concurrent archive/send in both orders, authority revocation, disk/process restart, cold wake, failed/ambiguous storage writes, forced stop, multiple writers and cleanup; then verify the isolated real application and UI. Preserve `UNKNOWN` rather than assuming a failed or interrupted write did not commit.

## Nondeployable shared-owner source experiment

`shared-owner-wip.patch` (SHA-256 `3edeec2653d3fd7290db9e67df7bc6a6ff76e0d4a28b20d3f9e0334a29ced15d`) is a separate zero-context patch against the same pinned base; it passed `git apply --unidiff-zero --check`. It includes a different test with the same filename as the baseline canary, so **do not apply the two patches together**. In a disposable copy, it adds a registry-queue admission method, checks target/ancestor archive state and rejects missing or cyclic ancestry, wraps the located Team→child, direct Subagent send, host queue/steer and cold-resume flows, and wraps the Team→Lead path. If the Workspace registry is absent, these wrappers fail closed. It does not modify installed code.

Targeted synthetic Host output: **5 passed, 1 expected fail**, not six passes. Passing cases cover archived child refusal across the four tested message routes, no cold resume until unarchive, same-ID resume after unarchive, missing authority and missing/cyclic lineage refusal, same-owner archive ordering and one Team-send-versus-pending-archive order. The expected-failure case shows that raw `Agent.steer` to an archived Lead remains **unwired and accepted**. Workspace remount uses the same in-memory storage pool; no process/disk restart was established. Retained `work/team-archive-evidence/shared-owner-final.log` SHA-256 `783716288b89bc138bdbb24f7faa69384e893cad56cafe48ba40085867334734`; matching pre/post input manifests SHA-256 `3103f8ac0d11ff64ab57b2f25fd4dc4b592b65d511bee340edf07458736ec6d2` include source, test, addon and patch hashes.

**Regression and blockers:** the pre-existing unarchived Team messaging test, run without a Workspace registry as supported by the pinned composition, now fails with `ARCHIVE_ADMISSION_UNKNOWN` (1 failed, 43 skipped; retained `work/team-archive-evidence/shared-owner-existing-regression.log`, SHA-256 `0b021e4378453a3eeca03e201072eb5fbe5c9a7ccdb716e58f87012f6afba330`). The source WIP therefore does not preserve all legitimate non-Team or registry-less behavior. The queue is local to one registry instance, not durable or cross-process; raw Agent inbox APIs, settlement wakeups, creation/initial prompts and possibly other entrypoints remain outside it. Holding a registry write queue across arbitrary async delivery can deadlock on reentrant registry operations and has not been proven safe. Durable storage failure, interrupted/unknown writes, competing owners, revocation, process restart and the opposite race order remain unproven. This WIP is a testable hypothesis, **not a safe gate**; never install it.

The Workspace and Team source `tsc --noEmit` checks passed. The Subagent source check initially failed because the local Workspace declaration was stale; after regenerating declarations in the disposable copy, it passed. This does not establish a distributable dependency closure, API compatibility or generated-code quality.
