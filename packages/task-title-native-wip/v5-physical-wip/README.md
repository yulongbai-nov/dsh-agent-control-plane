# Experimental V5 physical-read and adjacent-migration fixture

This is a nondeployable synthetic experiment against pinned public upstream `b830ec950faba0a46dda564be3e2d854afed94f1`. It creates a separate experimental catalog using the genuine Session format machinery and released V4 physical codec, adds a strict V5 decoder for the unchanged V4 event vocabulary, and adds an adjacent V4→V5 pass-through edge. It does not register with the installed catalog, change any Session format constant, add a task-title writer, or integrate with actual SessionPersistence. The experimental encoder accepts an entire validated V4-compatible fixture artifact to produce physical rows in memory; direct catalog header/event writing is disabled. Seeded Session migration and recoverable-tail mode fail closed; no task provenance or arbitrary future title-source kind is introduced.

The retained focused test passed 3/3 under a reviewed sandbox denying network and specified installed-app/profile paths. It uses synthetic physical JSONL in a fixture-owned temporary directory and the actual pinned V4 catalog/validator: a V4 user-pinned title plus unknown ignorable plugin record round-trips via the experimental V5 catalog; the pinned V4 catalog classifies V5 unsupported and rejects restore; unknown title source, malformed sequence and seeded migration are refused. A deliberately incomplete V5 staging file leaves the original V4 file byte-identical. This simulates interruption before publication; it is **not** an injected process crash, durable atomic migration, recovery or rollback test. No actual JSONL persistence service or old-reader write test is claimed by this new test; the separate earlier V5-reader probe covered pinned JSONL read/write rejection on a synthetic file.

## Lower-level JSONL generation experiment

A separate 3/3 synthetic test uses the actual pinned V4 JSONL SessionPersistence writer and lower-level `prepareJsonlMigration` stage/exclusive publisher with the experimental V5 catalog, a **test-owned in-process V5 verifier**, and a fresh task-owned root. The production JSONL service and its isolated verifier remain hardwired to V4; no production V5 reader or writer is installed. Two concurrent preparations in the same process converge on one V5 target; V4 source bytes, user-pinned title, an ignorable event and unseeded parent metadata survive, and pinned V4 SessionPersistence read and write reject after V5 appears. A changed source before publish is refused. Seeded migrations and a gapped source are refused; actual fork/replay and cross-process concurrency are not tested.

Two counterexamples remain explicit. The pinned scanner ignored an incomplete final JSON fragment as a torn tail; the test observed that behavior and did not publish it, so a production migration needs a source-integrity and truncation policy atomically tied to the verified source. An abort after `prepare` did not cancel `publish`: the target was committed despite abort. The pinned service checks abort immediately before starting publication and again before handing out the write handle, but the publish operation itself is uncancellable. Already-aborted callers can fence before invocation; late abort/interrupt needs target reconciliation and must not be blindly retried or treated as proof of no commit. The earlier 1-pass/1-fail test assuming truncated tail rejection and 2-pass/1-fail test assuming abort prevents publication remain retained outside the repository as `work/host-tests/title-v5-generation-v1.log` SHA-256 `f0d385cee12552604b20b75e1a57ba1e4e243ac7c804094596eeff4183d10fba` and `work/host-tests/title-v5-generation-v3.log` SHA-256 `8a1fff0df194b034611185a8ee2655eb57c79b65e68f8a49127462f16b3d7486`.

## Expanded synthetic generation and process boundaries

The later `title-v5-generation-expanded.spec.ts` and `title-v5-generation-child.spec.ts` passed 5/5 under the same restricted sandbox using real pinned JSONL generation machinery and the test-owned V5 verifier. The writer fixture now includes a complete synthetic user/model turn, fallback and provider titles referencing its user message, a user-pinned title, and an unknown ignorable event. The restored V5 artifact matches those events and preserves unseeded parent metadata; this is representative coverage, not proof of the full V4 vocabulary. A well-formed seeded V4 fork is accepted by the pinned old catalog but deliberately rejected by the experimental edge before publication, with source unchanged. Supporting inherited cuts and real forks remains blocked.

Two independent task-owned child processes prepared the same V4 source and successfully converged on one V5 target. Two further direct children were terminated with `SIGKILL` at controlled generation barriers: before source recheck the V5 target was absent; just after publication a V5 target existed and decoded with the experimental catalog. In both cases original V4 bytes were unchanged, each child was awaited, and the fixture removed its own root. This is not a power-loss, filesystem fsync, process-restart recovery, or mixed-version writer test. The target after publication is a potentially committed result even if a caller is interrupted; do not assume a failed/cancelled caller means no effect. The torn-tail and late-abort caveats and failed observations above remain unchanged.
