## 0. 进入安装测试前的硬门槛

每项必须有证据，缺失、歧义或任何反向 canary 失败均 **停止；不换路径重试，也不在用户环境试错**：

- [ ] **范围与授权：**用户明确批准具体版本、交付物、目标环境、测试和可能产生的写入/网络/模型动作；确认预计影响、停止条件及回退负责人。启动进程、安装、改配置、外发、删除及真实用户数据访问分别获得适用授权。本清单本身不是授权。
- [ ] **可验收交付物：**发布包版本、内容、校验值、依赖和目标 DSH 构建可审查并通过安全评估；功能边界、未实现项和互斥项已记录。当前本仓库仍是开发原型，没有能宣称满足 R1–R18 的完整安装包。
- [ ] **验证隔离：**优先专用隔离系统账号或 VM。新建专属测试 workspace、配置、session、browser user-data、缓存、日志和临时目录；审计最终解析路径及 symlink/hardlink，不与用户目录、运行中 GUI 或其他进程共享。审查并隔离 `HOME`、`DSH_HOME`、`DSH_AGENTS_HOME`、XDG、cwd、临时目录及浏览器数据，并以 allowlist 构建环境，剔除凭据、代理、Node 注入等继承项。**仅换 profile 名或设置一个 home 变量不等于隔离。**
- [ ] **隔离正反证明：**按 [隔离 GUI 方案的五类门槛](../packages/sandbox-e2e/README.md#进入真实-e2e-的门槛)验证文件、凭据/Keychain、IPC、子进程、网络、浏览器及目标服务身份；用专用合成 canary 做正向对照与拒绝测试。仅设置 loopback host 或现有 sandbox 片段不足以证明网络隔离。禁止连接或替换既有 GUI，不假定固定端口；服务和浏览器启动必须获得额外明确授权。
- [ ] **离线 fixture：**审查最小 profile 和激活组件，使用合成 session/Agent/来源记录和不访问网络的 fake provider；默认组合可能含凭据、持久 session、遥测、定时任务或外部工具，不能默认安全。不得使用 `--from-default-profile` 路径；它在 rc.5 某些情况下可能替换同名 profile。不得为绕过隔离或版本校验安装包、改兼容豁免或发网络请求。
- [ ] **快照与回退计划：**在用户授权范围内记录目标、精确文件清单、安装前版本/构建、配置及其不存在状态、权限和完整性，取得可恢复快照；先在合成隔离环境证明恢复路径、正确目标、空间和权限。快照可能含敏感内容，应隔离、限权，不放入仓库或公开日志；不得将脱敏副本当作可恢复备份。明确是否涉及数据格式/迁移及其可逆性，未确认时不执行。不得凭猜测覆盖、删除、降级或恢复用户文件。
- [ ] **命令审查：**由 Lead 为上述已验证环境编制并审核与目标版本一致的具体安装、验证、回退和清理步骤，逐条显示解析后的绝对目标、环境、预计写集、权限、预期结果与失败处置；操作者与用户确认后方可执行。**现阶段没有已验证的命令、已批准目标或可恢复快照。**

> CR-010 将真实 desktop 配置改动交 Lead 单独提出、按项目约定快照及用户授权后处理；本研究任务和本页均不授权触碰它。不要修改签名应用的 `app.asar`，也不要用 `compatibility.json` 豁免代替兼容测试。

## 1. 未来模板：安装与验收顺序（全部未实测）

1. **记录基线。** 在已批准且证实隔离的环境，记录 DSH/Node/Electron 版本与构建标识、插件版本及摘要、精确环境与配置来源、运行实例身份、预先存在的内容、截图/日志留存与权限；这些记录不得包含 token、凭据、用户路径或用户正文。证据对应的组件和版本不能省略。
2. **验证原生基线。** 安装前先在同一隔离环境证明原生启动、会话导航和必要功能正常，保存可对照的非敏感结果；确认没有真实外部连接及测试边界越权。
3. **按审核方案单步安装。** 核实每一步目标及写集与获批的一致；确认 manifest、peer/`engines.dsh`、宿主/客户端依赖、`dsh.bundle.patch`、`dsh.client` 和 patch 引用均受审。仅安装明确授权的可验收交付物；研究型 workflow fork 和与现有 provider 冲突的标题原型不得捆绑或激活。插件发现、构建产物与加载顺序必须经实际回执核对，**出现警告、冲突、不可预期写入或未能证明隔离即中止**。
4. **在批准的隔离 GUI 验证。** 仅连接受控启动回执指定且经进程/socket 身份核验的地址；经审查的 build/reload 或重启方式应对应实际插件与 shell 工件。若目标不能确认、连接令牌可能泄露或服务身份改变则停止；不宣称已有 GUI 会自动热更。
5. **逐项填写下表并留证。** 按产品明确支持的功能版本逐项执行；未开发、不可达或未执行填 `未测试/不适用及原因`，不得勾选通过。安装失败也必须记录失败与实际回退状态，不抹去失败证据。
6. **在同一隔离环境演练卸载/回退。** 使用事先审核的逆操作和验证方法逐项回到基线；结果及有无残留按下节记录。任何不确定的有损动作均暂停并请用户/Lead 决策，不自行清理目录。

## 2. 未来回滚步骤与验收（全部未实测）

以下仅为事先制订操作计划的顺序，不含会作用于实际用户环境的命令：

1. **停止与隔离。** 停止新增安装操作及向该实例发送任务；确认目标是测试实例，再以已获批方式停止受影响服务与子进程，保留受控日志并避免泄露 token。不得中断、替换或连接其他正在使用的 GUI/会话。
2. **查明变更。** 对照安装前快照、目标真实路径、版本、当前变更和写入清单，核实没有用户或其他操作者的并发改动；如目标、文件身份、快照完整性或写集不明，停下升级处理，不强制覆盖或删除。
3. **恢复配置和组件。** 仅在已授权目标中按已演练的逆序，恢复安装前配置与版本；区分原本不存在与空文件、禁用与卸载。保留签名 app 原样；未经单独授权不替换任何 app/profile。若发生不可逆 schema 迁移或数据写入，不盲目用旧版本打开，先按受审迁移/恢复方案处理。
4. **验证原生恢复。** 同版本下确认原有 slot/provider、会话导航、语言和其他扩展仍在，测试实例启动正常；对比配置与组件版本、权限、文件清单和已批准数据一致性，记录残留、不可逆影响和未知项。插件标记消失本身不证明恢复成功。
5. **结束与证据。** 记录恢复完成或失败、适用版本、可复现证据和未决项；仅清理得到用户授权的专属测试产物。任何不确定或可能属于用户的数据均不删除；保留必要的受限快照供经授权恢复。

如果出现拒载、应用启动失败或版本升级不兼容，先按 [升级冒烟与拒载回退](upgrade-smoke.md) 分支处理；当前没有可声称已验证的旧版回退方案。
