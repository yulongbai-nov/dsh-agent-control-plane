# DSH 版本升级与拒载回退冒烟清单（CR-009，未来模板）

> **状态：未执行。** 当前没有完成验收的完整插件包，没有已证明安全的真实隔离 GUI，也没有经过实测的安装、升级、降级或回滚。本文不是启动、安装或修改配置的授权，所有勾选项为未来待验项目。任何一个版本或环境的通过也不能自动推广到另一个 rc。

适用未来候选产品的版本维护和审查；先满足 [安装及隔离前置门槛](install-and-acceptance.md#0-进入安装测试前的硬门槛)。**未取得用户对目标、写入和启动的明确授权之前，不运行升级；不修改用户 profile、已签名 app、已有 GUI 或会话。** 不给出未经验证的升级/恢复命令；可执行步骤待交付物和隔离环境固定后由 Lead 单独审核。不要复制或继承用户环境来凑一个测试环境。

## 0. 比较前建立证据与拒载策略

- [ ] 记录旧版和候选版各自 DSH 精确版本、构建或签名身份、Node/Electron 版本、相关官方包版本、插件包及 fork 的版本和摘要、依赖及 manifest。不得把目前 `0.2.1-rc.5` 基线误作未来版本兼容性证明。
- [ ] 固定候选插件支持范围、可审查的小 fork diff 与依赖；核对 `engines.dsh`、peer、运行平台和构建资产。版本、schema 或 seam 未识别时**拒载或禁用受影响组件**，给可见原因；静态标记匹配也不能替代运行验证。
- [ ] 分别保存隔离测试环境的旧版可恢复基线及针对版本迁移的合成数据；记录具体文件、哈希、权限、原不存在状态、存储格式及迁移方向。未经验证的新格式写入不可用旧版盲读，先确认只读/备份/可逆迁移。不存在可恢复方案即中止升级。
- [ ] 预定义哪些差异属于正常降级、整组件拒载或必须停止：包括缺失服务、slot 冲突、未知事件/投影版本、权限能力缺口、用户 pin 不可保护和来源不可信。所有不确定值必须保留 unknown，不以空值或假成功代替。
- [ ] 先用已审查的离线合成 fixture、fake provider 和隔离数据演练；如需实际启动服务或 GUI，另有用户授权并完成文件、凭据、网络、浏览器及进程隔离正反验证。不连接或替换已有 GUI。

`compatibility.json` 的精确版本豁免（若在未来环境存在）不是 ABI、事件、权限或行为兼容性证明；**不得为了通过检查而修改豁免或关闭版本门**。rc.5 源码分析与旧测试只提供线索，不承诺目标版本也相同；patch 失配可能导致启动失败，不能假定最坏只是跳过插件。

## 1. 每个新 rc 的审查和冒烟矩阵

每项填写 `通过 / 失败 / 未测试 / 不适用（原因）`、旧/新精确版本、隔离环境、操作者、非敏感证据与失败处置。当前全部 **未测试**；没有完成且通过的必需项，不发布或推广到用户环境。

| 项目 | 比较及未来合成验证 | 当前 |
|---|---|---|
| 分发与版本门 | 比较打包资源、`engines.dsh`、peer、构建产物和依赖；支持版本正常装载；不支持版本经真实目标路径拒载并显示原因；故意缺包/资产时保留明确失败 | 未测试 |
| 插件加载 / 生命周期 | Host 与 client 的真实注册、依赖注入、卸载/重载、配置 patch 引用顺序及清理；无重复注册、错用旧 bundle、启动 crash 或静默半加载 | 未测试 |

## 2. 拒载、失败与回退决策树（仅未来模板）

**A. 支持范围外、缺证据或版本门拒载**

1. 保持扩展未启用；收集脱敏错误和版本信息，不改 `engines.dsh`/peer/豁免来强行加载。
2. 在隔离实例确认原生功能、其他扩展和现有配置仍可用；若连原生无法启动，转 B。仅声明「安全拒载」在实际完成这些检查后才成立。
3. 需要该功能时，先完成目标版本适配、审查和上述完整矩阵；否则保留未支持状态，**不宣布升级成功**。

**B. 候选使隔离实例启动失败、冲突或部分加载**

1. 停止继续改动，确认进程/路径属于授权测试环境，保留不含敏感数据的错误和状态；不自动重试、覆盖、不改签名 app。
2. 对照事前快照与写集，在确认无并发改动及迁移风险后，由负责人按已审核的逆序恢复该隔离环境的配置/组件；必要时仅禁用受影响组件。路径不明、快照不完整或副作用未界定时暂停，交负责人处理，不能保证一条通用命令能恢复。
3. 重启（如已授权）并验证原生 UI、其他插件、slot/provider、配置、版本和数据一致性；仍失败则保持故障并记录，不得称回退完成。

**C. 需要退回旧版**

1. 不把安装包回退、插件回退和数据回退混为一谈：先确认每个组件的确切旧版本、签名/完整性、与当前运行时及数据格式兼容，且有相应用户授权和已验证的恢复路径。
2. 如新版本已写入旧版不识别的持久格式或执行不可逆迁移，先停写并保全当前状态；没有经过审查的数据迁移/恢复方案时，不让旧版打开该数据，不删数据、不强制覆盖。
3. 在隔离环境按已验证方案恢复旧版与匹配配置，再重复原生功能、权限、旧事件回放和 GUI 检查；标明不可恢复/unknown 与实际证据。**当前没有已验证的旧版可用包或回退演练结果。**

后续若涉及用户真实配置，必须另走 CR-010：用户明确批准，Lead 按项目约定先取得安全快照并审查具体写集和回退计划；该流程未在本任务执行。完整测试、评审和用户同意之前，本页不产生安装或升级指令。
